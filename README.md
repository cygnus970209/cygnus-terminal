![Cygnus의 터미널, 서버별 명령 기록, SFTP 파일 패널](docs/media/workspace.png)

Cygnus는 여러 서버와 네트워크 장비를 오가며 작업하는 사람을 위한 데스크톱 터미널입니다. 접속 정보뿐 아니라 서버별 명령 기록, 자주 쓰는 명령, 경로, 자격 증명까지 한곳에서 관리합니다.

**Rust 백엔드와 운영체제의 WebView를 사용하는 Tauri 구조**로, 별도의 Chromium 런타임을 앱에 묶지 않습니다. 메모리 부담을 줄이는 가벼운 구조를 지향합니다. 실제 메모리 사용량은 운영체제·탭 수·작업에 따라 달라지며, 비교 벤치마크 수치를 주장하지 않습니다.

> 화면은 예시 데이터를 넣어 촬영했습니다. 서버 주소·파일·자격 증명 항목은 데모용입니다. 작업 공간 이미지는 v0.1.15의 Connections 탭 제거·탭 고정·히스토리 액션 추가 이전이며, Vault 이미지는 v0.1.13 개편 이전 화면입니다.

## 주요 기능

| 필요한 작업 | Cygnus에서 할 수 있는 일 |
| --- | --- |
| 서버·장비 접속 | SSH, WinRM, Telnet, Serial, 로컬 셸, RDP(Beta)를 하나의 탭 작업 공간에서 사용 |
| 반복 접속 | 프로토콜별 연결 저장, 그룹 선택, 즐겨찾기, 검색·필터 |
| 비밀번호 입력 | 암호화 Vault와 서버별 연결, SSH 프롬프트에서 자격 증명 선택·입력 |
| 파일 관리 | SFTP 전용 창, 로컬·원격 양쪽 패널, 서버 간 전송, 전송 상태 확인 |
| 반복 명령 | SSH 서버별 히스토리, 명령·경로 북마크, 공용 스니펫 |
| 운영 점검 | CPU·메모리·디스크 모니터, 여러 로그 스트림, SSH 로컬 포트 포워딩 |

## 접속부터 정리하는 Connections

![SSH, Telnet, Serial 연결을 함께 관리하는 Connections 화면](docs/media/connections.png)

- **SSH**: 비밀번호·키 인증, Jump Host, Agent Forwarding, 호스트 키 확인.
- **RDP (Beta)**: **New connection → RDP (Beta)**에서 Windows 데스크톱 연결을 저장하고 같은 목록에서 검색·즐겨찾기·연결·편집·삭제.
- **WinRM**: Windows 관리 연결을 저장하고 PowerShell 스크립트 실행·출력 확인·중지.
- **Telnet**: 레거시 서버와 네트워크 장비 접속.
- **Serial**: COM/TTY 장치 경로와 baud rate 저장. 장비가 꽂혀 있지 않아도 연결 정보를 준비할 수 있습니다.
- **Local Shell**: 필요할 때 탭으로 여는 로컬 터미널.

SSH·WinRM·Telnet·Serial의 그룹은 한 번 연결에 저장하면 다음부터 목록에서 선택합니다. 프로토콜·그룹 필터와 즐겨찾기로 원하는 연결을 찾고, **저장**과 **저장 후 연결**을 구분해서 사용할 수 있습니다. RDP 연결은 현재 그룹을 지정하지 않습니다.

탭을 드래그해 순서를 바꾸고, 우클릭 메뉴에서 **이 탭을 제외하고 닫기 / 왼쪽 닫기 / 오른쪽 닫기 / 고정**을 사용할 수 있습니다. **F10**은 활성 탭의 고정을 전환합니다(Mac 키보드 설정에 따라 **Fn+F10**). 고정 탭은 왼쪽에 모이고 일괄 닫기에서 제외되며, 해당 탭의 닫기 버튼이나 **Close tab**으로 직접 닫을 수 있습니다. 고정·일반 탭은 각각의 영역 안에서 정렬합니다. 탭에 포커스를 두고 **Shift+F10**을 누르면 같은 메뉴가 열립니다.

Connections는 사이드바 하단의 **Connections** 또는 명령 팔레트의 **Open Connections**에서 엽니다. 탭 줄 왼쪽의 패널 버튼으로 사이드바를 접거나 펼칠 수 있습니다. Connections로 돌아가도 세션은 유지됩니다.

## WinRM 연결

**새 연결 → WinRM**, 탭의 **+ → WinRM 연결**, 상단 **연결 → 새 WinRM 연결**에서 Windows 관리 연결을 추가합니다. SSH 서버 설치와는 별도로 대상 Windows의 WinRM 리스너, 계정 권한, 방화벽 설정이 필요합니다. [Microsoft 설정 문서](https://learn.microsoft.com/en-us/windows/win32/winrm/installation-and-configuration-for-windows-remote-management)를 참고하세요.

- 기본값은 **HTTPS / 5986 / NTLM**입니다. HTTP / 5985는 NTLM 메시지 암호화를 사용하며 신뢰할 수 있는 네트워크에서만 사용하세요. Basic은 HTTPS에서만 선택할 수 있고 서버에서도 활성화되어 있어야 합니다. Kerberos·CredSSP는 현재 제공하지 않습니다.
- 도메인은 사용자 이름과 별도 입력합니다. HTTPS는 시스템에서 신뢰하는 인증서를 검증하며, 자체 서명 인증서는 별도로 확인한 SHA-256 지문을 지정할 수 있습니다. 지정한 지문은 서버 인증서를 직접 신뢰하므로 인증서 교체 시 갱신해야 합니다.
- 암호를 입력해 저장하면 앱의 기존 암호화 저장 방식을 사용합니다. 비워 두고 연결 시마다 입력할 수도 있습니다. 편집에서 빈 암호는 기존 값을 유지하지만 호스트·포트·계정·전송 방식이 바뀌면 기존 암호를 제거합니다. 백업에는 암호와 인증서 지문을 포함하지 않습니다.
- 연결 탭에서 PowerShell 스크립트를 작성하고 **실행** 또는 **Ctrl/⌘+Enter**로 실행합니다. **중지**, 연결 해제, 탭 닫기는 실행 중인 원격 명령의 종료와 셸 정리를 요청합니다. 네트워크가 끊어졌을 때 원격 정리를 보장할 수는 없습니다.
- 각 실행은 새 비대화형 PowerShell 프로세스입니다. 변수·현재 디렉터리는 다음 실행에 유지되지 않으며 대화형 입력, 전체 화면 프로그램, SFTP는 제공하지 않습니다. 명령은 최대 5분, 출력은 1 MiB, 탭에는 최근 실행 5개를 보관합니다.

## 메뉴와 언어 설정

상단 **연결** 메뉴에서 SSH·로컬 셸·RDP·WinRM·Telnet·시리얼 연결을 열 수 있습니다. **도구** 메뉴에는 SFTP, 스니펫, 보관함, MCP 설정, 명령 팔레트가 있습니다. **Esc**는 맨 위 대화상자나 열린 선택 목록을 닫습니다. 호스트 키·권한 승인창에서는 요청을 거절합니다.

**설정 → 일반 → 언어**에서 English / 한국어를 선택하세요. 모든 창에 즉시 적용되고 다음 실행에도 유지됩니다. 처음에는 시스템 언어를 따르며, 한국어 이외에는 영어를 사용합니다. 서버 출력과 사용자 데이터는 번역하지 않습니다.

## 자격 증명을 기억하는 Vault

![서버별 비밀번호와 키 암호를 관리하는 Vault](docs/media/vault.png)

매번 비밀번호를 복사하고 붙여 넣는 대신, 서버에 맞는 자격 증명을 선택하세요.

- 비밀번호, SSH 키 암호, SSH 키, PAT 사용자명·토큰 항목 관리.
- 하나의 항목을 여러 서버에 연결하고 적용 범위 관리.
- 자격 증명·연결 서버 검색과 유형별 필터. 같은 창에서 항목을 편집하고 삭제 전 확인. 비밀 값을 비워 두고 편집하면 기존 값을 유지합니다.
- SSH 세션의 `sudo`·비밀번호·키 암호·Git HTTPS 비밀번호 프롬프트 감지와 입력 후보 제공. 감지 패턴은 **Settings → Autofill**에서 변경할 수 있습니다.
- 로컬 비밀 값은 **AES-256-GCM**으로 암호화하고, 마스터 키는 운영체제 자격 증명 저장소에서 관리합니다.
- **Vault 입력 동작은 Rust 백엔드에서 복호화 후 SSH 채널에 직접 전달**합니다. 이 과정에서 복호화된 비밀번호를 화면으로 반환하거나 클립보드에 복사하지 않습니다.

현재 비밀 값 입력은 Cygnus에 로컬 저장한 항목의 SSH 입력을 지원합니다. 외부 비밀번호 관리자 연동은 현재 제공 기능으로 안내하지 않습니다.

기본 비밀번호 패턴은 `[Pp]assword(?: for '[^'\r\n]+')?:\s*$`로, `Password:`와 `Password for 'https://user@github.com':`를 감지합니다. 기존 기본 규칙은 업데이트 시 보완하며, 직접 추가·수정하거나 삭제·비활성화한 규칙의 설정은 유지합니다. 직접 등록한 `[Pp]assword:\s*$`는 `for '…'` 부분을 허용하지 않으므로 Git HTTPS 프롬프트에도 사용하려면 패턴을 바꿔야 합니다.

앱 시작과 목록 조회만으로는 키체인에 접근하지 않습니다. 암호화 키가 처음 필요한 작업에서 안내 화면을 보여주고 **Continue**를 누른 뒤 운영체제 권한을 요청합니다. macOS의 **항상 허용(Always Allow)**은 해당 Cygnus 키체인 항목의 반복 승인을 생략하는 선택입니다. 안내 확인은 기억하지만 운영체제 권한을 대신 허용하지는 않습니다. **허용(Allow)**만 선택하면 앱을 다시 실행할 때 Cygnus 안내 없이 macOS 권한 창이 다시 나타날 수 있습니다. 앱 서명이나 키체인 권한이 바뀌면 항상 허용 후에도 재승인을 요청할 수 있습니다. [Apple 키체인 권한 안내](https://support.apple.com/guide/keychain-access/kyca1243/mac)

키체인 접근을 거부하면 Cygnus 안내창이 다시 열립니다. **Retry access**로 권한을 다시 요청하거나 **Cancel**로 작업을 중단할 수 있습니다. 취소해도 다음 접근 시 안내가 다시 표시됩니다. Termius 가져오기는 별도 안내를 사용합니다.

## 파일 작업은 SFTP 전용 창에서

![원격·로컬 파일을 나란히 보는 SFTP 전용 창](docs/media/sftp.png)

터미널 상단의 **SFTP Files**를 누르면 오른쪽 파일 패널이 열립니다. 패널의 **Open SFTP window** 버튼으로 더 넓은 파일 작업 공간에 바로 진입할 수 있습니다.

- 양쪽 패널에서 로컬 또는 원격 서버 선택, **서버↔서버 전송**.
- 드래그 앤 드롭, 다중 선택, 업로드·다운로드, 이름 변경·폴더 생성.
- 전송 진행률·속도·취소, 파일명 충돌 시 덮어쓰기·건너뛰기·다른 이름 보관.
- 로컬↔원격 폴더 동기화와 실행 전 차이 확인.
- 원격 파일을 로컬 편집기로 열고, 저장한 변경 사항을 자동 업로드.

## 서버마다 이어지는 작업 맥락

저장된 SSH 연결에서는 왼쪽 **Server tools**에 익숙한 작업을 모아 두었습니다.

- **History**: 실행한 명령 검색, 다시 실행, 우클릭으로 전체 명령어 복사·Commands에 저장. **Delete all…**은 확인 후 현재 서버의 기록 전체를 삭제하며, 검색으로 숨겨진 기록도 포함합니다.
- **Commands**: 자주 쓰는 점검·재시작·배포 명령 북마크.
- **Paths**: 자주 가는 디렉터리 북마크.
- **Ports**: SSH 로컬 포트 포워딩 관리.

공용 **Snippets**, `⌘/Ctrl K` 명령 팔레트, 크기 조절 가능한 패널로 반복 작업을 줄입니다. 자동 경로 추적은 **OSC 7 경로 정보를 보내는 셸에서만** 동작하며, 앱이 `pwd`를 끼워 넣지 않습니다.

서버 모니터와 로그 뷰어는 별도 SSH 채널을 사용합니다. 터미널에서 작업하면서 자원 상태와 여러 로그를 함께 확인할 수 있습니다.

터미널 입력·붙여넣기와 저장 명령 실행에서는 일반 공백처럼 보이는 **NBSP(U+00A0)를 일반 공백으로 변환**합니다. `sudo su` 같은 명령이 하나의 이름으로 처리되는 오류를 방지합니다. 따옴표 안의 텍스트에도 적용됩니다.

일반·MCP 터미널에서 Mac은 `⌘V`, Windows/Linux는 `Ctrl+V`, `Ctrl+Shift+V` 또는 `Shift+Insert`로 붙여넣습니다. 우클릭 메뉴의 **Copy / Paste**도 사용할 수 있습니다. 복사는 Mac `⌘C`, Windows/Linux `Ctrl+Shift+C`이며 `Ctrl+C`는 명령 중단으로 유지합니다.

## AI 도구와 연결하는 MCP

Settings → MCP에서 공유할 SSH 서버를 선택하고 로컬 MCP 서버를 켤 수 있습니다.
외부 AI 클라이언트가 서버 목록을 조회하고, 명령 실행 권한을 켠 경우 작업을 제출하고
결과를 조회·취소할 수 있습니다. **OAuth 앱 승인(Beta)**으로 URL만 등록한 뒤 Cygnus에서
브라우저의 확인 코드를 대조하고 승인할 수 있습니다. 토큰은 자동 갱신되며 승인 내역은
재시작 후에도 유지됩니다. 앱 재시작 시 MCP는 꺼져 있고, 다시 시작하려면 동의가 필요합니다.
Settings → MCP의 **Authorized clients**에서 개별 접근을 해제할 수 있습니다. 수동 토큰 연결도 지원합니다.
SFTP 조회·변경 권한을 별도로 켜면 파일 목록·메타데이터·읽기·쓰기·폴더 생성·이름 변경·삭제도
사용할 수 있습니다. 파일 본문은 요청당 최대 64KiB이며 Cygnus 실행기록에 저장하지 않습니다.
[설정 방법과 제공 도구](docs/guides/mcp.md)를 참고하세요.

Settings → Data → Execution history에서 작업 기록 저장·보관 기간·삭제를 관리합니다. 새 설치는 저장 꺼짐이며, 저장을 켜면 기본 7일간 암호화하지 않은 명령·출력을 보관합니다.

| macOS · Apple Silicon | `.dmg` — Developer ID 서명·공증 적용 |
| Windows · x64 | `.msi` 또는 `.exe` — 현재 Windows 코드 서명 미적용 |

설치된 앱은 GitHub Releases를 통해 업데이트를 확인합니다. Linux와 Intel Mac용 설치 파일은 현재 릴리스 대상에 포함되지 않습니다.

v0.1.13부터 개인 프로젝트 식별자를 사용합니다. 기존 연결·Vault DB와 암호화 키는 원본을 남긴 채 이전하며, 테마·즐겨찾기 같은 일부 화면 설정은 다시 지정해야 할 수 있습니다. [앱 식별자 변경과 데이터 이전 안내](docs/guides/app-identity.md#한국어)

연결 프로필과 명령·경로 북마크는 JSON으로 내보내고 가져올 수 있습니다. 이 내보내기는 비밀번호·Vault·스니펫을 포함하는 전체 백업이 아닙니다.

## 다른 터미널에서 이전

Connections의 **Import connections**에서 OpenSSH 설정과 iTerm2 프로필(JSON·plist)을 미리 보고 선택해 가져올 수 있습니다. 로컬 설정 자동 감지, 중복 제외, 미지원 설정 안내를 제공합니다. macOS에서는 Termius 10.1.0 로컬 접속 정보 직접 가져오기도 실험적으로 지원합니다. 비밀번호와 개인키 내용은 이전하지 않습니다. [지원 범위와 사용법](docs/guides/connection-import.md)

## 로드맵

**다음 방향은 여러 서버를 한 번에 관리하는 운영 자동화입니다.**

Ansible처럼 서버 그룹을 대상으로 명령·설정 변경·배포를 실행하고, 서버별 결과를 확인하는 고급 기능을 계획하고 있습니다. 현재 버전에는 포함되지 않으며 제공 범위와 일정은 추후 안내합니다.

## 개발하기

React·TypeScript·xterm.js 화면과 Rust 백엔드를 Tauri 2로 연결합니다. 데이터는 로컬 SQLite에 저장합니다.

Rust 1.98.0 (`rust-toolchain.toml`로 고정), Node.js 22.12+, 운영체제별 Tauri 빌드 도구가 필요합니다. 아래 예시는 패키지 관리에 Bun을 사용합니다.

```sh
bun install --frozen-lockfile
bun run tauri dev

# 검증
bun run build
bun run test
bun run rdp:build # Cargo를 직접 실행하기 전에 RDP 엔진 준비
bun run rdp:test
cargo test --manifest-path src-tauri/Cargo.toml --locked

# 설치 파일 빌드
bun run tauri build
```

RDP 베타는 **New connection → RDP (Beta)**에서 설정하고 **Save** 또는 **Save & Connect**로 사용할 수 있습니다. 저장한 RDP는 Connections와 사이드바에서 검색·즐겨찾기·연결·편집·삭제할 수 있습니다. 탭의 `+ → RDP desktop (Beta)`에서도 바로 열 수 있습니다. 연결 화면에서 주소·계정·도메인·해상도·Windows 배율(DPI)을 이름과 함께 저장하고, 수정하거나 다른 이름으로 복사할 수 있습니다. NLA/NTLM 직접 연결, 화면 표시와 기본 US 키보드·마우스 입력을 지원합니다. IIS 조회 화면도 실서버 검증이 진행 중인 베타로 표시합니다.

RDP 인증서의 SHA-256 지문을 직접 확인한 뒤 비밀번호를 입력합니다. 지문 기억은 선택 사항이며, 저장된 지문이 달라지면 이전·새 지문을 비교하고 변경을 확인해야 진행할 수 있습니다. 인증서 발급자·호스트 이름·유효기간 자동 검증은 아직 지원하지 않습니다. 비밀번호는 저장하거나 MCP에 제공하지 않습니다. 백업 v6에는 RDP 배율과 WinRM 프로필을 포함한 연결 설정을 저장하고 인증서 신뢰는 포함하지 않으며, 기존 v1–v5 백업도 가져올 수 있습니다. 배율이 없는 기존 연결은 서버 기본값을 사용합니다.

연결 중 툴바나 연결 종료·실패 화면에서 `Reconnect`를 누르면 같은 탭의 마지막 서버·계정·해상도·DPI 설정으로 다시 연결합니다. 편집 중인 다른 연결 설정은 유지합니다. 이전 연결이 종료된 뒤 새 연결을 시작하며 인증서 확인과 비밀번호 입력을 다시 거칩니다. 비밀번호 재사용이나 자동 재접속은 하지 않습니다.

한글은 연결 후 `Text input / 한글`을 열고 로컬 IME로 조합한 뒤 `Send text`로 원격 창의 입력 위치에 전송합니다. 조합 중 키와 Enter는 전송하지 않으며, 문자는 기록하지 않고 전송·닫기·탭 전환·앱 포커스 이탈 시 초안을 비웁니다. 단일 행, 최대 256 UTF-16 단위까지 지원하며 제어 문자는 차단합니다. 원격 프로그램의 Unicode 입력 지원에 따라 동작이 달라질 수 있습니다. 원격 화면 위에서 직접 조합하는 방식은 아직 지원하지 않습니다.

`Fit to window`는 창 크기에 맞춰 표시하고, `1:1 pixels`는 모니터의 DPI를 반영해 원격 픽셀과 실제 화면 픽셀을 맞춥니다. 연결 해상도는 최대 1920 × 1080이며, Windows 배율은 연결 시 요청합니다. 서버가 기존 세션의 배율을 유지할 수 있습니다. Windows 설치 파일은 CI에서 빌드하지만 설치한 앱과 실제 Windows 서버의 연결 검증은 더 필요합니다. RD Gateway는 아직 지원하지 않습니다.

서버가 Display Control을 지원하면 연결 중 `Remote resolution → Apply resolution`으로 해상도를 바꿀 수 있습니다(최대 1920 × 1080, 서버 허용 범위 내). 변경 중 원격 입력은 잠시 멈추고 서버가 확정한 크기로 화면을 갱신합니다. 서버가 요청을 무시하면 15초 후 안내하며 기존 연결을 유지합니다. 저장 프로필과 재접속에 사용할 최초 연결 설정은 바꾸지 않습니다. [Microsoft의 Display Control 전제 조건](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpedisp/2878b488-794e-42c1-8f98-a23fa950def8)에 맞춰 RemoteFX 코덱을 요청하지 않으므로 화면 전송량이 증가할 수 있습니다.

`Clipboard` 패널은 세션마다 직접 허용하는 일반 텍스트 공유입니다. `Load local clipboard`로 내용을 확인·편집한 뒤 `Send to remote clipboard`를 누르거나, 원격 앱에서 복사한 뒤 `Read remote clipboard → Copy preview locally`로 가져옵니다. 공유를 허용하면 원격 클립보드가 초기화될 수 있으므로 원격 텍스트는 허용 후 복사하세요. 자동 동기화·자동 붙여넣기·파일·이미지 공유는 하지 않습니다. 최대 2048 UTF-16 단위이며 줄바꿈·탭을 허용합니다. 터미널에 여러 줄을 붙여넣으면 명령이 실행될 수 있으므로 내용을 먼저 확인하세요. 패널 닫기·탭 전환·앱 포커스 이탈·재접속 시 공유 권한과 미리보기를 지우며, 이미 상대 컴퓨터가 받은 데이터는 회수할 수 없습니다. 공유 내용은 프로필·백업·실행 기록·MCP에 저장하거나 제공하지 않습니다. 진행 중 요청을 취소하거나 10초 내 응답이 없으면 늦은 응답 혼동을 막기 위해 재접속 전까지 클립보드를 잠급니다. RDP 화면 연결은 유지합니다.

RDP 엔진은 SSH와의 암호화 의존성 충돌을 피하기 위해 별도 Cargo 프로젝트로 빌드하고 앱에 포함합니다. `tauri dev/build`는 엔진을 자동으로 준비하며, 앱과 엔진은 로컬 파이프로 통신합니다. Rust 테스트나 `cargo check`만 직접 실행할 때는 먼저 `rdp:build`를 실행하세요.
